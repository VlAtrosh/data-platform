# data-platform · МДК.04.01 «Технология разработки и защиты баз данных»

Ваш репозиторий на весь год. Здесь живут стенд, по которому поднимаются все
хранилища курса, работы с занятий и домашние задания. К концу 8 семестра это
и есть **DATA PLATFORM v1.0** — то, что вы защищаете на дифференцированном
зачёте.

Год начинается с MongoDB, дальше в тот же стенд добавляются PostgreSQL,
ClickHouse, Redis и RabbitMQ. Репозиторий не переписывается — он дописывается.

## Сделать репозиторий своим

Нажмите **Use this template → Create a new repository**, назовите
`data-platform` и выберите видимость. У вас появится собственный репозиторий
с чистой историей, он остаётся у вас и после дисциплины. Форк для этого
не подходит: он остаётся привязан к исходному репозиторию.

```bash
git clone <адрес вашего репозитория> data-platform
cd data-platform
```

## Установка

Нужны три вещи. Ставятся один раз на весь год.

| Что | Зачем | Где взять |
|---|---|---|
| **Docker Desktop** | поднимает сервер базы данных в контейнере | [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/) |
| **MongoDB Compass** | графический клиент: показывает данные, типы и результат запроса | [mongodb.com/try/download/compass](https://www.mongodb.com/try/download/compass) |
| **git** | сдача работ | [git-scm.com](https://git-scm.com/downloads) |

Docker в этом списке — способ курса, а не требование Compass: Compass лишь
клиент и подключается к любому серверу MongoDB. Если Docker Desktop не встаёт,
берите локальную установку сервера или бесплатный кластер Atlas — команды
и разбор ошибок в [`stend/SETUP.md`](stend/SETUP.md).

На странице Compass выбирайте пакет **Compass** — полную версию. Readonly
не умеет писать, Isolated обрезает сетевые запросы; для занятий нужна полная.

Проверка, что Docker готов:

```bash
docker --version
docker compose version
```

Обе команды должны напечатать версию. Если вторая ругается — откройте
Docker Desktop и дождитесь, пока значок кита перестанет мигать.

## Запуск стенда

```bash
cd stend
docker compose up -d      # поднять сервер
docker compose ps         # статус должен стать healthy
```

Сервер слушает `localhost:27017`. Строка подключения для Compass:

```
mongodb://localhost:27017
```

Полный сброс — когда нужно начать с чистой базы:

```bash
docker compose down -v    # ключ -v удаляет данные вместе с контейнером
docker compose up -d
```

Без `-v` том переживёт перезапуск, и коллекция останется заполненной.

### Если Compass пишет ошибку

| Сообщение | Причина | Что делать |
|---|---|---|
| `connect ECONNREFUSED 127.0.0.1:27017` | сервер не запущен | `docker compose ps`, при статусе `Exited` — `docker compose up -d` |
| `Server selection timed out` | адрес недоступен | проверьте, что в строке `localhost`, а не опечатка |
| `port is already allocated` | порт занят другим стендом | поменяйте левое число в `docker-compose.yml` на `27018` и подключайтесь к нему |

## Структура

```
stend/                  общий стенд курса: docker-compose.yml и учебные данные
  seed/resumes.json     девять резюме — загружаются в Compass через ADD DATA
  seed/companies.json   справочник компаний (занятие 2)
  seed/resumes_embed.json   те же резюме с вложенной компанией
  seed/resumes_ref.json     те же резюме со ссылкой company_id
  seed/interviews.json      приглашения — вторая копия названия компании
  SETUP.md              три способа поднять сервер, если Docker не встаёт
  queries.mongodb.js    запросы занятия 1 в исполняемом виде
lesson_01/              занятие 1: MongoDB, документ, BSON, первая коллекция
lesson_02/              занятие 2: embedding и referencing, ADR-002, замеры
  queries.mongodb.js    три счёта: чтение, отчёт, правка
  grow.mongodb.js       предел документа: доводим массив до отказа
  scale.mongodb.js      большая база: 20 000 резюме и 5 000 компаний
lesson_03/              занятие 3: практическая работа «Каталог товаров»
  homework_03.md        отчёт, шесть скриншотов и три контрольных вопроса
docs/git/               разбор git в VS Code со скриншотами
```

На каждое занятие с домашней работой — своя папка. Папку для следующего
занятия делаете копией предыдущей: `cp -r lesson_01 lesson_02`
(на Windows — `Copy-Item -Recurse lesson_01 lesson_02`).

Что сдавать и что проверяется — в `README.md` внутри папки занятия. Там же
чек-лист, который проходят перед Pull Request.

## Как сдавать

```bash
git switch -c hw-01                  # ветка на задание, номер по папке
git add lesson_01
git commit -m "hw-01: коллекция резюме, шесть запросов, разбор дубликата"
git push -u origin hw-01
```

Дальше на GitHub открываете **Pull Request** в свою `main` и коротко пишете:
какая предметная область, чем отличаются формы документов, что оказалось
неожиданным. Merge делаете сами после проверки. Срок — до начала следующего
занятия.

Всё то же самое делается мышкой в VS Code, без терминала. Разбор со
скриншотами: [коротко](docs/git/README.md) — основные операции,
[подробно](docs/git/FULL.md) — каждый шаг, включая типичные ошибки.

## Правила

- **Стенд должен подниматься у другого человека** после `git clone` и чтения
  вашего README. Это и есть главная проверка работы.
- Числа в отчётах сверяются с вашей базой на приёмке: скриншот без
  работающего стенда не принимается.
- ИИ можно просить причесать формулировки и оформить `.md`. Запросы, планы
  и вывод команд должны быть получены на вашем стенде — на приёмке вы
  объясняете каждый принятый вариант и показываете фактический вывод системы.
- Пароли, ключи и строки подключения к чужим серверам в репозиторий
  не кладём. Для этого есть `.env`, и он в `.gitignore`.
